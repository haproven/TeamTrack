# TeamTrack

## Mini Team Project

TeamTrack is a lightweight team record dashboard for maintaining a simple and organized record of team members, their roles, departments, current projects, start dates, and work status.

The project will be developed as a **team collaboration project**, where all members work together, discuss the project, understand the requirements, help each other, test the work, review changes, and learn the complete GitHub development workflow.

The main goal is not only to complete the project, but to **build it together and understand how the project is being built**.

---

## Project Goal

The dashboard should answer these basic questions:

* Who is working on the team?
* What is their role?
* Which department are they in?
* Which project are they currently working on?
* When did they start?
* Are they currently active?
* Where can their complete profile be found?

Detailed personal and professional information will remain on the member's HaproID profile instead of being duplicated in this project.

# Team Collaboration

TeamTrack will be developed **together as one team**.

The team will not simply divide the project into separate parts and work independently without understanding the complete project.

Before development starts, the team will discuss the project together and make the important decisions collectively.

### Team Working Process

```text
Team Discussion
       ↓
Understand the Project
       ↓
Discuss Ideas & Questions
       ↓
Make a Common Decision
       ↓
Start Development
       ↓
Work Together & Help Each Other
       ↓
Test
       ↓
Review
       ↓
Fix Issues
       ↓
Complete the Project
```

### Everyone Should Understand

Every team member should have a basic understanding of:

* What we are building
* Why we are building it
* How the project works
* How the code is structured
* What other members are working on
* How their changes connect with the rest of the project

A member does not need to know everything from the beginning.

If something is not understood, they should ask the team.

### Team Help

If a member does not understand something:

1. Ask the team.
2. Explain the problem clearly.
3. Another member explains the concept or approach.
4. Discuss the solution together.
5. The member continues the work after understanding it.

Members are encouraged to teach and help each other.

The purpose is:

> **Work together, understand together, and learn together.**

# 5-Day Roadmap

## Day 1 — Discussion, Understanding, Decision & Setup

**No coding starts immediately.**

First, the complete team will discuss the project together.

The team will discuss:

* Project purpose
* Required features
* Dashboard layout
* How the project should work
* JSON structure
* File structure
* GitHub repository
* Git workflow
* Development approach
* Testing method
* Team responsibilities

If anyone has a different idea or does not understand something, it will be discussed before development starts.

### Day 1 Result

By the end of Day 1, everyone should understand:

> **What we are building, why we are building it, how we will build it, and how everyone's work connects together.**

Only after the team understands and agrees on the basic structure will development begin.

---

## Day 2 — Development

Development starts after the team discussion and decisions are complete.

The team will start building the project together.

Possible development areas:

* HTML structure
* Dashboard UI
* CSS styling
* JSON data
* JavaScript functionality
* Member list
* Status system

Members can work on different files or sections when required, but the development will follow the **same team-decided structure and approach**.

If someone gets stuck, they should ask the team instead of working with an unclear approach.

---

## Day 3 — Integration

On Day 3, the team will bring the developed parts together and make sure everything works as one project.

Tasks may include:

* JSON integration
* Dynamic member rendering
* Search
* Filters
* HaproID links
* Project links
* Responsive layout
* Code integration
* Fixing integration problems

The team will check whether everyone's changes work correctly together.

All important changes should go through GitHub.

---

## Day 4 — Testing & Bug Fixing

The team will test the complete project together.

Testing should include:

* Desktop
* Mobile
* Search
* Filters
* Links
* JSON loading
* Missing data
* Missing images
* Responsive layout
* Console errors
* UI issues
* Basic user experience

If someone finds a problem, they should explain it to the team.

The responsible member will work on the fix, while other members can help understand or test the solution.

After fixing, the change should be reviewed and tested again.

---

## Day 5 — Final Review & Completion

The complete team will perform the final review.

Final tasks:

* Bug fixing
* Code review
* UI review
* Responsive testing
* Final integration
* README update
* Repository cleanup
* Final testing
* Final pull requests
* Merge approved changes
* Final project check

### Final Result

By the end of Day 5, the team should have:

* A working TeamTrack project
* Clean and understandable code
* Tested features
* Reviewed changes
* Updated documentation
* A properly organized GitHub repository

# Working Time

There is **no fixed working time** for team members.

Everyone can work according to their own schedule.

The important thing is not working at the same time every day.

The important things are:

* Understand the project
* Follow the common decisions
* Complete the work within the deadline
* Share important updates
* Ask for help when needed
* Help other members when possible
* Participate in discussion and review
* Inform the team early about blockers

### Important

A member does not need to wait for everyone before working.

They can continue their work according to their availability, but they should stay connected with the team's decisions and updates.

If an important change is being discussed, the team should discuss it together before changing the agreed approach.

The general workflow will be:

```text

   ↓

   ↓

   ↓
Develop
   ↓
Test
   ↓
Commit
   ↓
Push
   ↓

   ↓
```

Unfinished or untested changes should not be pushed directly to `main`.

# Team Learning

TeamTrack is also a learning project.

A member may know one technology better than another member.

For example:

* One member may understand CSS better.
* Another may understand JavaScript better.
* Another may understand GitHub better.
* Another may be better at testing.

Members should share their knowledge with each other.

No member should feel that they have to solve everything alone.

### Team Principle

> **If you know something, explain it.
> If you don't know something, ask.
> If someone is stuck, help them.**

---

# Testing & Review

Testing is not only one person's responsibility.

Every team member can test the project and report problems.

Before the final merge, the team should check:

* Does the feature work?
* Does it work on mobile?
* Does it work on desktop?
* Does the data load correctly?
* Are links working?
* Are there console errors?
* Does the UI look correct?
* Does the change affect another part of the project?

The purpose of review is not to find someone's mistake.

The purpose is to **make the project better together**.
