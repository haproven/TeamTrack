# TeamTrack

## Mini Team Project

TeamTrack is a lightweight team record dashboard for maintaining a simple and organized record of team members, their roles, departments, current projects, start dates, and work status.

The project will be developed as an open mini team project where team members can work together, help each other, review code, test features, and learn the complete GitHub collaboration workflow.

---

## Project Goal

The dashboard should answer these basic questions:

- Who is working on the team?
- What is their role?
- Which department are they in?
- Which project are they currently working on?
- When did they start?
- Are they currently active?
- Where can their complete profile be found?

Detailed personal and professional information will remain on the member's HaproID profile instead of being duplicated in this project.

This is an open team project.

- Help another member

# 5-Day Roadmap

## Day 1 — Discussion, Decision & Setup

Before writing code, the team will discuss and finalize:

- Project purpose
- Required features
- Dashboard layout
- JSON structure
- File structure
- GitHub repository setup
- Team responsibilities
- Branch strategy
- Commit rules
- Pull request process
- Testing method

### Day 1 Result

Everyone should clearly understand:

> What we are building, how we are building it, and what their responsibility is.

**No fixed working time is required.**

Each member can choose their own working time.

However, all important decisions and updates must be shared with the team.

---

## Day 2 — Development

Start implementation after the Day 1 decisions are complete.

Possible tasks:

- HTML structure
- Dashboard UI
- CSS styling
- JSON data
- JavaScript rendering
- Member list
- Status system

Team members can help each other whenever required.

---

## Day 3 — Integration

Combine all developed parts.

Tasks:

- JSON integration
- Dynamic member rendering
- Search
- Filters
- HaproID links
- Project links
- Responsive layout
- Component/code integration

All important changes should go through GitHub.

---

## Day 4 — Testing & Bug Fixing

The project will be given to team members for testing.

Test:

- Desktop
- Mobile
- Search
- Filters
- Links
- JSON loading
- Missing data
- Missing images
- Responsive layout
- Console errors
- UI issues

Bugs should be reported through GitHub Issues or the team's discussion channel.

After testing, the responsible member fixes the issue and submits the changes for review.

---

## Day 5 — Final Review & Completion

Final tasks:

- Bug fixing
- Code review
- UI review
- Responsive testing
- Final integration
- README update
- Repository cleanup
- Final testing
- Final pull requests
- Merge approved changes
- Final project check

### Final Result

The project should be completed and ready for use by the end of Day 5.

---

# Working Time

There is **no fixed working time** for team members.

Each member can work according to their own schedule.

However:

- Tasks must be completed within the assigned deadline.
- Important updates must be shared with the team.
- If a member is stuck, they should ask for help.
- If a member cannot complete their task on time, they should inform the team early.
- Team members should remain available for necessary discussion and review.
